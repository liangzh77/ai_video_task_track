# 功能规格说明：任务跟踪与模板管理系统

**功能分支**: `001-task-tracker`
**创建日期**: 2025-12-12
**状态**: 草稿
**输入**: 用户描述："任务跟踪网站，包含用户认证和基于模板的内容管理"

## 澄清记录

### 2025-12-12 会话

- Q: 谁可以创建模板和任务？ → A: 管理员不能创建模板，只能管理用户（查看、重置密码、修改权限）。有 CRUD 权限的普通用户可以对模板和所有任务进行增删改。
- Q: 管理员重置密码时，新密码是什么？ → A: 重置为固定默认密码 "123456"。
- Q: 删除模板时，其下的任务如何处理？ → A: 级联删除，模板及其下所有任务一起删除。
- Q: 用户是否可以删除单个图片或文案？ → A: 可以，有 CRUD 权限的用户可以删除单个图片或文案。
- Q: 没有模板时页面显示什么？ → A: 显示空白页面，用户自行寻找创建入口。

### 边界情况

- 用户上传无效文件类型（非图片）时会发生什么？
  - 系统显示错误消息并拒绝文件
- 系统如何处理多用户并发编辑？
  - 采用后写入覆盖策略；用户刷新后看到更新的数据
- 管理员重置自己的密码时会发生什么？
  - 管理员可以重置自己的密码，但之后必须重新认证
- 所有用户都被删除时会发生什么？
  - 管理员账户不能被删除；始终至少存在一个管理员
- 用户将图片/文案拖到其组外时会发生什么？
  - 拖放限制在组内；无法将图片移到文案区域或反之

## 需求 *(必填)*

### 功能需求

**用户管理**
- **FR-001**: 系统必须支持两种用户角色：管理员和普通用户
- **FR-002**: 系统必须提供预配置的管理员账户（用户名：admin，密码：admin123）
- **FR-003**: 管理员必须能够查看所有注册用户列表
- **FR-004**: 管理员必须能够将任意用户的密码重置为默认密码 "123456"
- **FR-005**: 管理员必须能够切换用户的 CRUD 权限
- **FR-006**: 管理员必须能够切换用户的批准权限
- **FR-007**: 管理员不能看到任务跟踪页面（仅管理员仪表板）
- **FR-007a**: 管理员不能创建、编辑或删除模板或任务（仅用户管理）
- **FR-008**: 普通用户必须能够注册新账户
- **FR-009**: 普通用户必须能够使用凭据登录
- **FR-010**: 新注册用户默认为只读权限（无 CRUD，无批准）

**内容 CRUD 权限（适用于有 CRUD 权限的用户）**
- **FR-010a**: 有 CRUD 权限的用户必须能够创建新模板
- **FR-010b**: 有 CRUD 权限的用户必须能够删除模板（级联删除：模板下所有任务一并删除）
- **FR-010c**: 有 CRUD 权限的用户必须能够在任意模板下创建新任务
- **FR-010d**: 有 CRUD 权限的用户必须能够删除任意任务

**页面布局**
- **FR-011**: 系统必须显示任务跟踪页面，左侧 2/3 为内容，右侧 1/3 为图片预览
- **FR-012**: 右侧 1/3 面板必须专门用于显示放大图片
- **FR-013**: 图片预览面板在滚动内容时必须保持可见（固定位置）

**模板与任务结构**
- **FR-014**: 系统必须支持多个模板（模板1、模板2、模板3 等）
- **FR-015**: 每个模板必须显示为单独一横行，包含：模板名称、图片组、文案组
- **FR-016**: 每个模板必须支持多个任务（任务1、任务2、任务3 等）
- **FR-017**: 每个任务必须显示为单独一横行，包含：图片组、文案组、备注、批准、制作人、上架时间、曝光、注册、利润

**图片管理**
- **FR-018**: 每个模板/任务必须支持多张图片
- **FR-019**: 图片必须以 100px 高度的缩略图显示
- **FR-020**: 点击任意图片缩略图必须在右侧预览面板显示大图
- **FR-021**: 模板/任务内的图片必须可通过拖放重新排序
- **FR-022**: 图片拖放必须限制在图片组内（不能与文案混放）
- **FR-023**: 图片上传必须支持拖放功能
- **FR-024**: 图片上传必须支持多文件选择
- **FR-024a**: 有 CRUD 权限的用户必须能够删除单张图片

**文案管理**
- **FR-025**: 每个模板/任务必须支持多条文案
- **FR-026**: 文案必须可通过拖放重新排序
- **FR-027**: 文案拖放必须限制在文案组内（不能与图片混放）
- **FR-028**: 所有文案字段必须支持行内编辑
- **FR-028a**: 有 CRUD 权限的用户必须能够删除单条文案

**任务字段**
- **FR-029**: 数字字段（曝光、注册、利润）必须只接受有效数字
- **FR-030**: 批准必须是复选框切换
- **FR-031**: 制作人字段在勾选时必须显示当前登录用户的用户名

### 关键实体

- **用户 (User)**: 系统中的账户。包含用户名、密码（哈希）、角色（管理员/普通用户）和权限（canCRUD、canApprove）
- **模板 (Template)**: 显示为一行的内容模板。包含名称、图片列表（有序）、文案列表（有序）。拥有多个任务。
- **任务 (Task)**: 模板下的任务项。包含图片列表（有序）、文案列表（有序）、备注、是否批准、制作人用户名、上架时间、曝光、注册、利润。

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 管理员可以管理（查看、重置密码、设置权限）100% 的注册用户
- **SC-002**: 用户可以在 1 分钟内完成注册
- **SC-003**: 用户可以在提交凭据后 5 秒内登录

- **SC-006**: 管理员所做的 100% 权限更改立即生效，无需用户重新登录
- **SC-007**: 所有数据在浏览器会话和服务器重启后持久化
- **SC-008**: 系统支持至少 10 个并发用户，无性能下降
- **SC-009**: 点击缩略图后 500ms 内在预览面板显示放大图片
- **SC-010**: 图片/文案拖放重新排序立即反映新顺序

## 假设

- 图片为标准网页格式（JPEG、PNG、GIF、WebP），合理的大小限制（5MB）
- 系统使用基于会话的认证以保持简单
- 数据存储在数据库中（具体技术在实施规划中确定）
- 应用程序是单租户系统（一个组织的数据）
- 模板和任务通过界面管理；授权用户可以添加/删除模板
- 数字指标（曝光、注册、利润）手动输入，非计算或导入
- 图片预览面板一次显示一张图片（最近点击的）
